# Founding member accounting baseline

November 26, 2026 · U.S. small-business scope

Sage Intacct is the model for fast, consistent reporting across dimensions. QuickBooks Online is the replacement and migration benchmark, especially for onboarding, accountant usability and integrations. Crossroads is the first operating example. The shared ledger must support the same accounting workflows for every member before we expand industry-specific features.

## What already exists in Crossroads

The repo has a tenant-scoped double-entry journal, cash and bank feeds, categorized and split transactions, matched booking payments, trial balance, P&L, balance sheet, account registers, exports, audit chain, close controls, and job and reimbursement subledgers. Booking journals connect job costing to posting lines, source records, voids and adjustments. This is a repository assessment. A signed-in production test and independent reconciliations are still needed.

**Shared foundations.** Accounts, journal and accounting periods, bank feeds and duplicate checks, vendor and customer references, exports, audit trail, expense evidence and approvals, and a project identifier belong in the shared product. The current job-tag and posting rules should remain readable during migration. Generalize them with a deliberate backfill and tie-out.

**Crossroads workflows.** WeddingPro lead reconciliation, booking and agreement status, officiant as a separate service line, ceremony or reception labor, crew mileage or expenses, deposits and balances, event-date revenue, job margins, commissions, cash/check pickup, and processor payouts. Keep planning, playlists, timelines and run sheets in the event module. Only post the resulting accounting events to the GL.

## Reporting dimensions

Use separate tenant-scoped dimension definitions, members and journal-line assignments keyed by stable IDs. Store account identity independently of location, department, project and other dimensions. Define allowed values, defaulting and required dimensions per posting rule. Keep dimensions optional while migrating and preserve unmapped values for review. Never infer missing job allocation from a contact name alone.

Reuse the same checked filter model for P&L, GL, budget comparisons, subledger views and exports. Users should be able to pivot one measure by department and location, filter by a third dimension, then follow any cell to the journal lines and evidence. Apply exactly the same filters to totals, drill-down and CSV. Distinguish unassigned values and retain historical labels or changes for audit. Test report tie-outs for multi-dimension splits and avoid fan-out multiplication when aggregating journal lines.

| Baseline | Suggested dimensions | Optional accounts and source integrations |
| --- | --- | --- |
| Professional and field services | Location, department, customer, job, service line | Client deposits, prepaid job costs, direct labor or materials, contract and time imports |
| Weddings and events | Location, customer, event, service line, lead source | Undeposited funds, deferred deposits, accrued crew or event costs, reimbursements and commissions |
| Retail and e-commerce | Location, channel, category, supplier | Inventory, COGS, clearing, shipping, merchant fees, gift-card liability, Shopify/POS |
| Food and hospitality | Location, department, channel, menu category | Food/beverage revenue and cost, inventory, tips payable, delivery clearing, POS and payroll |

Onboarding should preview a versioned chart before applying it. Match by account semantics and explicit mapping. Existing account numbers stay in place even when the starter chart suggests a different code. Changes to presets affect new selections and go through a separate, audited migration for existing workspaces.

## Migration and integration hub

1. **File-first conversion.** Export [QuickBooks reports and lists](https://quickbooks.intuit.com/learn-support/en-us/help-article/list-management/export-reports-lists-data-quickbooks-online/L1xleDrLp_US_en_US), then map stable IDs, dates, currency, account and dimension references. The first shipped slice is browser-local preflight for a normalized CSV. Next, build raw report adapters and persistent, permission-controlled import staging with source provenance, checksum, previews and exact rejection reasons.
2. **Safe posting.** Post only after tenant-level approval with server validation, period checks, idempotency on tenant/provider/company/object/version, balanced entries and an audit row in the same transaction. Import through either opening balances plus open items or historical detail, with overlap checks so the same activity cannot be counted twice. Preserve source identifiers and attachments independently of provider names.
3. **Direct connectors for unattended sync.** Use [Intuit OAuth](https://developer.intuit.com/app/developer/qbo/docs/develop/authentication-and-authorization) and its company identifier with a tenant-owned provider connection. Encrypt tokens server-side, isolate connector permissions by tenant, support revocation, redact logs and create a scoped sync queue with checkpointing, retries, a failed-job queue and operator replay. Validate [webhook](https://developer.intuit.com/app/developer/qbo/docs/develop/webhooks) authenticity before queueing. Re-fetch authoritative data, backfill missed changes and treat deletes and corrections as versioned events. Start read-only and choose an explicit system of record per data type before outbound sync.
4. **Chat as another interface.** Expose a small set of typed [MCP tools](https://developers.openai.com/api/docs/guides/tools-connectors-mcp) for trial-balance reads, report drill-down and reconciliation exceptions. Use the same tenant and role checks as the web app, enforce allowed fields, and return source links. Connected chat apps can help gather documents or prepare mappings when the user has authorized them. Provider sync, posting and money movement stay behind ERP services and their approvals. Never give Chat raw connector credentials, arbitrary SQL, bulk payroll details or autonomous posting permissions.
5. **Cutover.** Reconcile trial balance by account, bank and card statements, open invoices and bills, inventory if applicable, deferred revenue, payroll clearing and tax control balances against the predecessor at the same cutoff. Compare income statement, balance sheet and the underlying reports over a parallel close. Have a bookkeeper resolve any difference and sign off before retiring QuickBooks for that member.
